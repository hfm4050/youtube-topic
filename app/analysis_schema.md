# analysis.json 스키마 (대시보드 「화면·대본 분석」 5개 탭용)

`reels/data/analysis/<id>/analysis.json` — `analysis.md` 와 같은 내용을 화면이 읽을 수 있는 구조로 담는다.
유효한 JSON(UTF-8, python `json.load` 가능)이어야 한다. 모르는 값은 `null` 또는 빈 배열. **지어내지 않는다.**

```json
{
  "hook": {
    "text": "0~3초에 나오는 원문 대사 그대로 (자막이 없으면 화면 자막에서 복원)",
    "source": "영어 원문 · 자막 | 한국어 원문 · 자막 | 화면 자막에서 복원 | 음성 없음",
    "type": "질문 | 결과 약속 | 반전 | 숫자 | 금지 | 공감 상황 중 하나",
    "flow": "이어지는 전개 (예: 결과 약속 → 실행 단계)",
    "ko": "후킹 대사의 한국어 번역 (원문이 한국어면 null)",
    "interpretation": "이 후킹이 왜 먹히는지 2~3문장",
    "frames": [ {"file": "f_001.jpg", "sec": 0, "desc": "이 프레임의 인물·자막·구도 한 문장"} ]
  },
  "structure": {
    "flow": "전개 순서 한 줄 (예: 후킹 1~2 질문→결과 약속 › 본문 3~11 실행 단계 › 행동 유도 12)",
    "units": [
      {"n": 1, "time": "00:00", "role": "후킹 | 본문 | 행동 유도", "type": "질문·결과 약속·실행 단계·해결책 소개·증거·전환·행동 요청 등",
       "original": "원문", "ko": "한국어 번역", "does": "이 대사가 하는 일"}
    ]
  },
  "screens": {
    "summary": "화면 구성 요약 2~3문장 (화면 종류 비율, 컷 길이, 자막 스타일, 전환 빈도)",
    "segments": [ {"time": "00:00–00:03", "kind": "말하는 얼굴 | 화면 녹화 | B롤 | 자막 카드 | 그래픽", "desc": "무엇이 보이는지"} ],
    "frames": [ {"file": "g_004.jpg", "sec": 9, "desc": "장면이 바뀌는 지점의 화면 설명"} ]
  },
  "translation": [
    {"time": "00:00", "role": "후킹 | 본문 | 행동 유도", "original": "단락 원문", "ko": "한국어 번역"}
  ],
  "insights": {
    "why": "왜 터졌나 — meta.json 의 수치(조회·좋아요·댓글·배수·참여율)만 근거로",
    "comments": "댓글이 붙는 지점 (확인 못 했으면 그렇게 적는다)",
    "borrow": ["구조에서 빌릴 것 1", "빌릴 것 2", "빌릴 것 3"],
    "verify": ["사실 확인이 필요한 주장 1", "…"]
  }
}
```

- `frames[].file` 은 `frames/` 폴더에 실제로 있는 파일명. `f_0NN.jpg` = N-1초, `g_NNN.jpg` = 3 + (NNN-1)×2 초.
- `hook.frames` 는 첫 3초(f_001~f_003 + g_001) 전부. `screens.frames` 는 장면이 바뀌는 곳 위주 6~12장.
- `translation` 은 대본 전체를 의미 단락 4~10개로 묶는다. 번역은 AI 초안이다.
- 문자열 안에 큰따옴표를 쓰지 않는다(작은따옴표로).
