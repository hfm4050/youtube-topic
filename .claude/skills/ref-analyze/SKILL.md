# 레퍼런스 분석 → 새 대본 5개 → 제작 기획

4단계: ① 레퍼런스 ② 화면·대본 분석 ③ 대본 5개 비교 ④ 제작 기획. 산출물은 `reels/data/analysis/<id>/`에 쓴다.

## ① 재료 받기
`python3 reels/scripts/fetch_ref.py <url|id> --frames` (인스타가 막히면 `--cookies-from-browser chrome`, 자막이 없으면 `--whisper`).
`meta.json`, `transcript.txt`, `frames/`를 읽는다. 화면은 Read 도구로 직접 본다(첫 3초 `f_0NN.jpg`는 전부, 이후 `g_NNN.jpg`는 장면이 바뀌는 곳 위주 8~12장).
대본을 못 얻었으면 화면 속 자막에서 복원하고 "화면 자막에서 복원"이라고 표시한다. 그것도 안 되면 멈추고 보고한다 — 대본을 지어내지 않는다.

## ② analysis.md (화면·대본 분석)
아래 다섯 부분을 이 순서로.
1. **첫 3초** — 초 단위로 대사와 화면(인물·자막·소품·구도)을 나란히. 후킹 유형 한 단어(질문/결과 약속/반전/숫자/금지/공감 상황).
2. **대본 구조** — 대본을 의미 단위 8~14개로 나눠 표: `단위 | 시간 | 역할(후킹·본문·행동 유도) | 유형(질문·결과 약속·실행 단계·해결책 소개·증거·전환·행동 요청…) | 원문 | 한국어 번역 | 이 대사가 하는 일`. 위에 전개 순서 한 줄(예: 후킹 1~2 질문→결과 약속 › 본문 3~11 실행 단계→해결책 › 행동 유도 12).
3. **화면 분석** — 시간대별 화면 종류(말하는 얼굴/화면 녹화/B롤/자막 카드), 컷 길이, 자막 스타일, 화면 전환 빈도.
4. **원문·번역** — 타임스탬프 단락별 원문과 한국어 번역 나란히. 번역은 AI 초안이며 음성 인식 오류 가능성을 명시.
5. **반응 인사이트** — 왜 터졌나(수치 근거: 배수·참여율), 댓글이 붙는 지점, 구조에서 빌릴 것 3가지, 내용 중 사실 확인이 필요한 주장.

## ③ scripts5.md (대본 5개)
- 대상 채널을 먼저 정한다(refs의 `fit`, 없으면 사용자에게 한 번 묻거나 가장 맞는 채널 1개를 골라 이유를 적는다).
- **빌리는 것은 구조다**: 단위 수, 역할 순서, 문장 틀, 컷 리듬. **내용·문장·예시는 전부 우리 채널 분야의 것으로 새로 쓴다.** 원문 번역을 그대로 옮기지 않는다.
- 5개는 서로 다른 주제·각도(예: 증상 신호 / 비용·기간 / 흔한 오해 / 상담실 질문 / 시즌 훅). 각 대본: 가제(≤50자) · 단위별 대사(원본 단위와 1:1 대응 표) · 예상 길이 · 필요한 화면 · 법규 체크 한 줄.
- 마지막에 비교 표: `No | 가제 | 후킹 문장 | 원본 구조 일치도 | 촬영 난이도 | 근거(이 주제가 우리 분야에서 반응 있다는 정황) | 추천`.
- 출연자 서사 넣기: 원장·교수·대표의 실제 경험이 들어갈 자리를 `[인터뷰 필요: …]`로 표시하고, 물어볼 질문 2~3개를 끝에 모은다. 경험담을 지어내지 않는다.

## ④ plan.md (제작 기획)
추천 1~2개에 대해: 컷 리스트(번호·초·화면·대사·자막), 준비물, 촬영 장소, 캡션 초안, 댓글 유도 문장, 썸네일/첫 프레임, 업로드 형식(릴스·쇼츠 동시 여부).

## 법규·금지 (docs/RUNBOOK-자동발행.md 기준)
의료광고법: 효과 보장·최상급·전후 비교·환자 유인 금지, 환자 미노출. 화장품법: 의약품 오인 표현 금지. 보험: 개별 약관 상이 명시. 스타라인은 안면거상·리프팅·눈수술만.
원본의 주장(수치·효능)은 검증 전에는 우리 대본에 옮기지 않는다.

## 마무리
`collect.py set <id> --note "분석 완료 · 추천 대본 N번"`, `dashboard.py` 갱신, 추천안과 인터뷰 질문을 보고한다.
